## 🐛 POTENTIAL PROBLEM SOURCES

### Issue 1: CSS Box Model Confusion
**Problem**: Multiple containers with dimensions can cause stacking issues

**Layers**:
1. `<html>` - 210mm × 297mm
2. `<body>` - 210mm × 297mm
3. `.preview-container` - 210mm × 297mm
4. `.o_report_layout_vpa` - 100% (= 210mm)
5. `.page` - 100% (= 210mm)

**Possible cause**: If `.o_report_layout_vpa` has margins/padding, the 100% will be INSIDE the padding, creating gaps.

### Issue 2: Header/Footer Element Spacing
**Problem**: Elements inside the layout have margins

```xml
<!-- Header has margin-bottom -->
<div style="padding-bottom: 15px; margin-bottom: 25px; border-bottom: 4px solid #875a7b;">

<!-- Table has margin-bottom -->
<table style="width: 100%; margin-bottom: 25px;">
```

These push content DOWN, but the footer is positioned at `bottom: 0`, so there's a gap.

### Issue 3: Footer Absolute Positioning
**Problem**: Footer uses `position: absolute; bottom: 0;`

If the content doesn't fill the page, there will be white space between content and footer.

### Issue 4: wkhtmltopdf Rendering Quirks
**Problem**: wkhtmltopdf doesn't always respect CSS perfectly

- `overflow: hidden` might not work
- `height: 100%` might not expand to full page
- Fixed positioning might have offsets
